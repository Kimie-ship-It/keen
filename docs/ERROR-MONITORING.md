# 错误记录与健康检查

## 已实现的范围

当前是本机原型的基础监控，不是公网全天候值守服务。网站接口、服务端未捕获请求异常、PostgreSQL 空闲连接异常、每日采集、同步和备份入口已接入统一故障记录。预期的参数错误、未授权、限速和不存在记录不当作系统故障。

接口发生内部错误时仍返回脱敏的 503，同时在响应头 `X-Error-Id` 给出随机故障编号。编号可以与本机记录对应；学生页面不显示内部错误详情。服务端页面异常由 Next.js `onRequestError` 记录，没有相应的接口响应头承诺。

## 记录与安全

- 只保存编号、时间、严重程度、固定操作名称、粗粒度错误类别、已知高校 ID，以及固定接口路径和 GET/POST 方法。
- 不保存原始错误消息或堆栈、数据库连接字符串、密码、口令、请求参数、请求头、请求体、IP 或招聘正文。新增通知只引用固定操作和故障编号，不转发原始错误。
- 本机日志位于 `data/logs/errors/`，按日期或单文件 2 MiB 上限轮换，保留最近 14 个匹配的文件，不是固定保留 14 天。读取忽略损坏记录，最多返回 500 条；默认 100 条。
- 新日志目录已被 Git 和 Vercel 上传规则排除。构建文件追踪不打包日志目录或本机配置。
- Vercel 环境只输出脱敏的结构化控制台记录，不写 serverless 临时磁盘；本机的查询命令不能读取未来云端日志。平台留存、日志转存和远程告警须上线后单独验收。
- 这些安全约束针对本次新增故障记录。Next.js 自身的控制台堆栈、已有采集运行日志和数据库内的历史来源错误不是本次统一记录的一部分，不能据此宣称全部历史日志已脱敏。

## 如何检查

在项目目录执行：

```powershell
npm run monitor:check
npm run monitor:errors
```

健康检查读取当前网站数据库：连接成功且招聘数量大于零才算数据库可用。未下架高校要求最近 36 小时内成功更新；最近一次采集失败也会提示异常。管理员主动下架的来源标为 `paused`，不计入采集故障。允许最多 5 分钟的时间偏差，不要求所有高校同一时刻更新。

备份检查要求本机最新 Supabase 加密快照能成功解密、包含新版来源下架历史，且创建时间不超过 36 小时。旧版七表快照标为 `incomplete`，不会仅凭时间新就判正常。它不会自动覆盖生产库，也不替代完整恢复演练。当前命令面向已配置 Supabase 及备份密钥的本机；无云端配置或无备份时提示异常属于配置边界，不会静默跳过。

全部正常返回 `status: ok` 和退出码 0。任一组件异常返回 `status: degraded` 和退出码 1，并生成对应脱敏记录。备份不可读不会被误报成数据库故障，数据库断开后仍会尝试检查备份。

## 每日任务和提醒

每日采集会在云端备份尝试后执行健康检查，即使全部高校采集失败也会尝试这两个步骤。本地备份、同步、云端备份、通知或健康检查异常都会让每日任务返回非零结果，不能将部分成功误认为全部正常。

仍使用现有 Windows 每天 08:00 的任务，依赖开机和登录。2026-10-01 手动触发现有计划任务，18:12:14 健康记录中数据库、四校更新和新版备份均为 `ok`，任务结果码 0；2026-10-02 任务在 09:04 左右运行，南开超时，健康状态为 `degraded`，结果码 1。当天运行不等于已经证明 08:00 准时触发；详见 `docs/DAILY-TASK-ACCEPTANCE.md`。本机停机时不会运行健康检查，因此不能监测自身完全停机。常驻采集模式保留原有采集用途，只增加故障记录，不替代每日备份与健康检查流程。

飞书机器人按用户决定暂缓。未配置 webhook 不发送提醒；已有配置时每日流程可以发送脱敏摘要，实际送达尚未验证。可选手动提醒命令为 `node scripts/monitor-health.mjs --notify`，没有配置时明确报告未发送，不会创建机器人。

- `npm run test:monitor-http` 启动独立临时网站，使用无法连接的假数据库；验证六个接口操作（含来源管理读写）的 503/故障编号与本机记录匹配，以及详情页未捕获异常记录。结束后关闭该临时网站，不改动正式数据库。
- 真正公网部署、独立探活、云端日志留存/转存、浏览器异常监控、远程告警实际送达与停机提醒仍未完成。不得把基础记录完成当作这些项目均已完成。
