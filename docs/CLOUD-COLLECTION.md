## 启动保护

1. 开关关闭时直接退出，不读取授权、不连接数据库、不采集或同步。
2. 开启后先检查Supabase模式、严格TLS、独立采集运行环境、绝对SQLite路径、已有备份密钥及异地上传配置。网站托管运行环境不得执行本入口。
3. 从项目外读取异地上传授权文件，仅检查结构；不在启动准备中刷新授权，不输出密钥。文件存在及结构有效不等于授权或真实上传已验收。
4. 只读检查现有SQLite完整性，不创建空库。只读、可重复读事务分批读取Supabase的五张采集表，并关闭连接。
5. 比对采集表全部字段和记录，包括招聘/运行编号、来源、地点、行业和来源状态；仅排除网站拥有的招聘审核状态。缺表、空库、旧副本、编号或内容不一致时停止，不能自动覆盖任一数据库以通过检查。
6. 通过后复用现有每日流程，保留官方来源限制、采集失败保留旧数据、云端管理状态保护、加密备份、异地上传及健康检查。每日流程返回异常时继续返回异常，不报成功。

启动检查不构成跨机器并发锁，也不保证检查后数据永远不变。切换前必须停止本机旧写入任务、同步到同一基线，并确认只有一个执行器；并发控制和安全交接尚待P03.2完成，不应提前开启。

- 持久化范围包含采集SQLite、采集快照、项目外本地/加密备份目录以及项目外授权文件；不要将密钥与数据副本公开或放入Git。当前备份目录仍为仓库旁的 `campus-jobs-backups`，不能只持久化SQLite就声称备份已保留。
- 服务端配置使用平台认可的密钥存储；采集器不需要网站管理口令、恢复目标数据库地址或暂缓的邮箱。不得默认启用飞书。
- 本机与云端不能同时作为采集写入方；确认单执行器及故障后的基线核对/回退流程，不能用关闭保护检查来处理不一致。
