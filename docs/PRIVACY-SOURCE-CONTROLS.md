# 隐私说明与来源下架

## 当前范围

网站 `/privacy` 说明收藏存储、搜索与导出请求、故障日志、第三方数据库、官方公告跳转和下架边界。首页和详情页提供入口，首页提供清空收藏。当前仍是四校本地试运行，不接收简历、不代投、没有学生账户系统，也没有自动全副本删除功能。

对外联系邮箱通过服务端 `PRIVACY_CONTACT_EMAIL` 配置。未配置时页面明确提示尚无联系渠道，不虚构邮箱、不收集投诉附件。正式公开前必须确认运营主体、有效联系渠道、实际数据库和托管地区及适用要求；本功能完成不代表法律或合规审核完成。

## 管理操作

1. 打开 `/admin`，输入本机管理口令，读取待审核。
2. 单条招聘的问题沿用隐藏操作。整所高校来源的问题在“高校来源”选择原因，再取消“公开展示”，确认后提交。
3. 列表、详情、筛选选项、高校来源、采集历史及收藏导出在新请求时排除该来源，跨校合并只保留仍公开的高校。来源下架优先于单条审核通过状态。
4. 每日、常驻、四个独立采集命令和地点补充在新来源批次开始前查询网站数据库的下架状态；读取失败时停止该批次，不默认继续采集。已经开始的请求或批次不会被强行取消。
5. 问题处理后勾选公开展示并确认恢复。单独隐藏的招聘不会随来源恢复而重新公开。

来源操作接口沿用管理认证及持久化失败限速。每次操作在 `source_controls` 追加审计记录，最新编号决定状态；插入失败不改变状态，管理页显示最近 50 条操作。操作者标记为共享口令“管理员”，不是独立用户身份审计。重复同类操作也会留下记录。

## 数据与迁移

`source_controls` 由网站数据库维护，不属于采集器同步的五张表。云端下架记录不会自动回写 SQLite。切换数据库、回退旧代码或恢复旧备份之前，必须另行迁移/核对云端下架记录与单条隐藏状态，不能因回退再次公开受限信息。旧版代码不认识来源下架，不能直接用于公开服务。

已存在初始结构的云端项目使用追加迁移，不改写 `0001_initial_schema.sql`：

```powershell
node scripts/migrate-sources.mjs --apply
```

命令先生成加密备份，再创建下架审计表并启用 RLS，最后核对已有表的行数。不应与采集同步并发执行，核对过程出现变化须检查是否有其他写入。2026-10-01 本机项目迁移成功，招聘仍为 4919 条，四个高校来源，来源下架记录为 0；没有为了测试而改变真实来源状态。

新版加密备份为 v2，包含八张业务表与下架历史。旧版 v1 七表备份仍可解密、隔离演练，但不能直接执行独立空库恢复；必须先核对缺失的下架历史。健康检查把旧版快照标为 `incomplete`，有意暂停的高校标为 `paused`，不报成采集过期故障。

## 请求处理与限制

联系渠道上线后，人工核对本网站链接、官方公告链接、影响范围和说明；先决定单条隐藏或整校下架，处理后复核新请求和采集状态。不要收集不必要的简历、身份证等敏感材料。收到彻底删除请求时另行评估并记录主库、SQLite、采集 JSON、日志与已有备份的处理结果，不把下架冒充彻底删除。

已经打开的页面、缓存或下载的 CSV 无法召回；刷新或重新导出以后以当前状态为准。当前机制按整所高校限制，不跨高校自动按公司下架；涉及多校公告要逐个核对。

## 验证

`npm test` 覆盖下架过滤、恢复不解除单条隐藏、采集与地点补充暂停、策略不可读时停止、联系方式校验和备份完整性检查。`npm run test:supabase` 与 `npm run test:cloud-backup` 在真实数据库的临时表中测试并回滚。`npm run test:sources-http` 使用独立临时 SQLite 网站，不写真实生产数据。

可选浏览器检查需设置 `CAMPUS_JOBS_PLAYWRIGHT_PATH` 指向本机 Playwright 模块；若没有其默认浏览器，设置 `CAMPUS_JOBS_BROWSER_PATH` 指向本机 Chrome。截图保存在被忽略的 `data/test-qa/source-controls/`，包含电脑和手机页面及交互检查，不保存真实管理口令。
