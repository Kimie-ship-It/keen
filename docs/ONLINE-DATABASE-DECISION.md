# 线上数据库选型记录

## 已选方案

**Supabase PostgreSQL**

当前项目使用 SQLite 保存招聘、来源状态、地点、行业和审核日志。线上部署改用 PostgreSQL，保留关系型表结构和服务端查询方式，避免把线上运行数据继续放在单台应用服务器的本地文件中。

## 选择理由

- 现有数据有多张关联表、唯一约束、索引和审核日志，PostgreSQL 与这些关系型需求匹配。
- Supabase 官方支持服务端和 serverless 运行方式；部署到 serverless 函数时使用事务连接池，并关闭 prepared statements。
- 后续可以继续使用 SQL、迁移脚本和常见数据库工具，不把项目锁定在某个前端 SDK 上。
- 管理后台、采集任务和公开查询可以共用同一个数据库，便于备份和恢复。

## 费用与边界

- 免费计划只用于迁移测试和小规模预览：数据库上限 500 MB，项目闲置 1 周后可能暂停。
- 正式公开运行前，需要根据访问量、数据增长和备份要求评估 Pro 计划及其他托管方式。
- 本记录只完成“选择数据库”，尚未创建线上项目、迁移生产数据或写入任何数据库密钥。

## 后续迁移顺序

1. 创建独立的 Supabase 测试项目。
2. 把 SQLite 表结构转换为 PostgreSQL 迁移脚本。
3. 导入一份本地备份，核对招聘数量、来源状态、地点、行业、审核日志和导出功能。
4. 将数据库访问封装为线上适配层，本地开发继续保留 SQLite；在适配层完成前不启用云端定时采集。
5. 通过线上适配层测试后，再配置后台定时任务并决定正式项目和线上数据切换时间。
