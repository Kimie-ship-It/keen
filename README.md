# 校招雷达

一个本地采集、云端展示的高校招聘信息中转站。当前接入北京航空航天大学、北京理工大学、北京交通大学和南开大学就业网，将公开招聘信息采集到本地 SQLite，再同步到 Supabase。本机网站已选择 Supabase 模式，搜索、分页、详情、收藏导出及管理审核均访问云端数据库；尚未发布为公网服务。当前上线路线不依赖云端采集器。

## 当前边界

- 已实现：北航、北理工、北交大与南开招聘采集、跨高校保守去重、失败保留旧数据、每日本机定时任务、公开查询页、浏览器本地收藏、口令保护的审核接口。
- 数据规模：以本机数据库实时结果为准，不在文档中写死条数。
- 尚未实现：更多高校采集器、用户账号、简历投递、线上部署、真实飞书机器人送达验证。
- 网站中的“查看官方公告”只是跳转到高校原始页面，不代表已经打通投递。
- 每个高校来源必须配置官方域名白名单；采集入库和公开接口都会过滤白名单外、带异常端口或带账号信息的链接。
- 未经人工审核的记录仍公开展示，并明确标为“待人工核验”；运营人员可以核验通过或隐藏。
- 同一公司、同一招聘标题至少出现在两所不同高校时，公开列表合并展示；单一高校内部记录不合并，数据库仍保留每所高校的原始记录和官方链接。
- 首页汇总异常高校数量；高校来源页与采集状态页逐校显示最近成功、最近失败和当前采集状态。任一来源超过 36 小时未成功采集或最近一次采集失败时提醒核对官方公告。该时间不代表每条公告都仍然有效。
- 招聘大厅支持服务端按高校筛选；筛选后搜索、分页、原始记录数、合并招聘数和统计数字均只针对当前高校，详情页只保留该高校的官方公告入口。
- 招聘大厅支持服务端按工作城市筛选。城市来自高校官方招聘详情中的结构化字段或公告正文；无法确认的记录显示“未注明”，不会用公司注册地替代工作地点。城市筛选可与高校和关键词组合。
- 招聘大厅支持服务端按行业筛选。行业由公司名、招聘标题和岗位类型按可解释的关键词规则推断，共 14 个类别；无法判断的记录归入“未分类”，不会把推断结果当成企业官方行业认证。行业筛选可与高校、城市和关键词组合。
- 招聘大厅支持服务端按截止日期筛选，提供尚未截止、7 天内截止、30 天内截止、已截止和未注明截止日期选项；日期以招聘公告中的截止日期为准，筛选可与高校、城市、行业和关键词组合。
- 招聘信息支持独立详情页，展示来源高校、发布时间、截止日期、招聘人数、工作地点、行业标签和审核状态；合并招聘保留各高校官方公告入口，页面只提供官方公告跳转，不代替投递。
- 招聘大厅支持导出收藏，收藏记录保存在当前浏览器本地；导出时按收藏键从网站数据库重新读取，生成 UTF-8 CSV，包含招聘摘要和官方公告链接，不会把管理口令或浏览器数据上传到服务器。

## 本地启动

需要 Node.js 20 或更高版本。

```powershell
npm install
npm run setup:local
npm run dev
```

浏览器打开 `http://localhost:3000`。审核页位于 `http://localhost:3000/admin`，管理口令保存在本机 `.env.local`，不要提交或发送给他人。

## 采集数据

手动采集单所高校的公开招聘信息：

```powershell
npm run collect:buaa
npm run collect:bit
npm run collect:bjtu
npm run collect:nankai
```

运行全部每日采集流程（包含可选通知）：

```powershell
npm run collect:daily
```

采集器会请求高校公开接口，按来源和招聘 ID 增量写入 `data/campus-jobs.db`。接口异常、空列表或中途失败时不会清空已有招聘记录。`data/*-recruitments.json` 是各高校便于排查的本地快照，不是网站的数据源。
`source_status` 表保存高校采集的最新状态和最近成功、失败时间；升级旧数据库时会从已有采集记录回填。公开接口按高校返回这些时间和是否超时，但内部错误详情不会对外返回。
每条记录还会生成稳定的 `dedupe_key`。去重只忽略大小写、空格和标点，并要求公司名称和招聘标题同时一致；公开列表按合并后的招聘分页，`stats.total` 仍表示原始记录数，`stats.uniqueTotal` 表示合并后的招聘数。

## 每日自动更新

在 Windows 上安装或更新每天 08:00 运行的计划任务：

```powershell
npm run schedule:install
```

任务名为 `CampusJobsRadar-Daily`，日志写入 `data/logs/collect-YYYY-MM-DD.log`。当前上线阶段就使用这项本机计划任务；计划任务只在这台电脑可用，关机错过时间后，Windows 会在条件允许时补跑。当前任务使用 Windows 交互式登录会话，用户退出系统或账户无法交互时可能不会执行。网站上线后，学生访问网站，网站从 Supabase 读取本机任务已经同步的数据；学生不需要访问你的电脑。

## 审核方式

1. 运行 `npm run setup:local` 生成管理口令。
2. 打开 `/admin`，输入 `.env.local` 中的 `ADMIN_TOKEN`。
3. 选择“核验通过”或“隐藏”。

管理页本身可以访问，但读取待审核数据和修改状态都必须通过管理口令。口令只保存在当前页面内存中，不写入浏览器存储。
管理页还显示最近 20 条审核操作；全部历史记录保存在当前网站数据库的 `review_events` 表中。Supabase 模式下日志保存在云端，不包含在 SQLite 备份中；八张业务表加密备份包含云端审核、审计及来源下架历史，每日在本机生成，2026-10-01 已手动上传一份加密副本至百度网盘。密码保护的U盘独立密钥保存及读回恢复复验已通过，见 `docs/USB-KEY-BACKUP.md`；每日自动上传仍待完成。当前使用共用口令，日志只能标记“管理员”，无法区分具体人员。
管理接口对连续错误口令限速：15 分钟内达到 5 次后错误请求返回 429；正确口令可清除失败计数。当前采用全局计数，线上部署时还需入口层按请求来源限速。

## 配置

复制 `.env.example` 的字段含义即可，不要把真实值提交到版本库：

- `ADMIN_TOKEN`：至少 24 个字符的管理口令，推荐由 `npm run setup:local` 生成。
- `FEISHU_WEBHOOK_URL`：可选，飞书自定义机器人 webhook。
- `FEISHU_SIGN_SECRET`：可选，机器人签名密钥。
- `COLLECT_TIMEOUT_MS`：单次请求超时，默认 15000 毫秒。
- `COLLECT_RETRIES`：请求重试次数，默认 3 次。
- `COLLECT_INTERVAL_MS`：常驻采集模式的间隔，默认 1 小时。
- `SUPABASE_DB_URL`：Supabase PostgreSQL 连接字符串。只写入本机 `.env.local` 或线上密钥管理器，不要提交到 Git。配置后，每日采集成功并完成本地备份后同步招聘、地点、行业、来源运行、来源状态这五张采集表，不上传本地审核日志和口令限速状态。
- `CAMPUS_JOBS_STORAGE`：网站数据库模式，允许 `sqlite`（未指定时的默认值）或 `supabase`。本机已设为 `supabase`，配置后需要重启网站；云端连接失败时接口返回 503，不自动回退到 SQLite。
- `SUPABASE_SSL_CA`：可选的可信 CA 证书 PEM 内容，可用 `\n` 表示换行。Supabase 主机默认使用随代码打包的官方公开 CA，其他数据库使用系统信任链；连接地址中的 SSL 参数不会覆盖验证策略。
- `SUPABASE_SSL_INSECURE`：仅用于本机诊断的证书校验例外，`1` 关闭校验，默认不开启。本机已设为 `0` 并使用官方 CA 连接成功；托管构建和 Vercel 运行时都拒绝关闭校验。
- `SUPABASE_BACKUP_KEY`：`setup:backup` 生成的业务备份加密密钥，仅保存在本机安全配置中。丢失后无法恢复已有备份，禁止公开或随意替换。
- `SUPABASE_BACKUP_RETENTION_COUNT`：保留有效加密备份的数量，默认 14。
- `SUPABASE_RESTORE_DB_URL`：仅实际恢复时配置的独立空库地址，不改变网站连接；禁止使用当前源数据库。

未配置飞书 webhook 时采集照常运行，只是不发送日报和故障提醒。

配置 Supabase 数据库连接时，不要把密码发到聊天或写进 Git。直接在本机运行 `npm run setup:supabase`，按提示输入密码（输入不会显示），然后运行 `npm run check:supabase` 和 `npm run sync:supabase`。

### 数据归属与回退

采集器始终写入本地 SQLite；云端模式的网站只读取 Supabase，不直接读取采集 JSON 快照。每日同步完成后，网站下次查询即可读取新信息。云端的审核状态、审核日志、登录失败计数和来源下架历史由网站维护；重复同步保留这些状态，新记录统一标记为待核验。同步拒绝空本地库及相同招聘在两端 ID 不一致的情况，防止关联错配。

SQLite 模式保留作开发和故障排查用途，不是无损生产回退。云端管理状态不会自动回写本地；切回 SQLite 或旧版代码之前必须核对并迁移审核与来源下架状态，避免再次公开受限信息。当前部署仍是本机网站加云端数据库，采集任务仍依赖本机开机和登录。

在目标飞书群创建“自定义机器人”后，在本机终端运行：

```powershell
npm run setup:feishu
npm run test:feishu
```

第一个命令只把 webhook 和可选签名密钥写入已被 Git 忽略的 `.env.local`，签名密钥输入时不会回显。第二个命令发送真实测试消息；只有目标群确认收到后，才算配置完成。不要把 webhook 或签名密钥发送到聊天、日志或代码仓库。

## 错误记录和健康检查

网站内部故障会生成脱敏记录，接口响应头提供 `X-Error-Id`；本机可运行 `npm run monitor:errors` 查询最近记录，运行 `npm run monitor:check` 检查数据库、四所高校更新状态和最新加密备份。2026-10-01 手动触发现有 Windows 每日任务，自动备份、健康检查及新备份恢复验收通过；下一次 08:00 时间触发尚待观察，见 `docs/DAILY-TASK-ACCEPTANCE.md`。Vercel 只输出结构化控制台日志；公网独立探活、云端日志留存和真实飞书告警仍待完成，详见 `docs/ERROR-MONITORING.md`。

## 隐私与来源处理

`/privacy` 提供隐私和下架边界说明；首页可清空本浏览器收藏。当前页面说明本服务由个人运营、面向中国大陆高校毕业生，暂不公开联系方式。后台可下架整所高校来源并暂停后续采集，恢复不解除单条隐藏。服务端可配置 `PRIVACY_CONTACT_EMAIL`，目前保持未配置；下架不是彻底删除，也不能召回已下载文件；操作、追加迁移和回退限制见 `docs/PRIVACY-SOURCE-CONTROLS.md`。

## 清单、备份和日志

- `docs/PROJECT-CHECKLIST.md`：项目总清单。每次开始任务先查看，完成并验证后再勾选。
- `docs/CHANGELOG.md`：重要变更日志，记录做了什么、为什么做以及验证结果。
- `npm run backup:step -- "步骤名称"`：创建一次步骤备份。它会提交当前代码到本地 Git，并把数据库和采集快照备份到项目外的 `campus-jobs-backups` 文件夹。
- `npm run backup:data`：手动创建运行数据备份。每日采集成功后也会自动执行，默认保留最近 14 份，可通过 `BACKUP_RETENTION_COUNT` 调整。
- `npm run backup:verify`：把最新备份恢复到临时目录并检查完整性和记录数量，不覆盖正在使用的数据库。
- `npm run backup:supabase`：手动生成八张云端业务表的 v2 加密快照，包含来源下架历史；每日采集流程也会尝试生成。
- `npm run backup:supabase:verify`：在 PostgreSQL 临时表中恢复并比较全部内容，结束后回滚，不覆盖正式数据。
- `data/logs/`：采集运行日志，记录任务实际运行过程，不等同于代码备份。

Git 用于回退代码，SQLite 备份用于恢复本地采集数据；`backup:step` 和 `backup:data` 不自动包含云端审核、审计、限速和来源下架变化。Supabase 加密快照覆盖八张业务表，但不是整个项目备份。2026-10-01 已手动上传一份至百度网盘，下载复验记录见 `docs/BAIDU-OFFSITE-BACKUP.md`；每日自动上传尚未配置。旧版七表备份仅支持解密和隔离演练，不能直接用于独立空库恢复。密钥和备份必须分别保护，恢复流程与未完成边界见 `docs/CLOUD-BACKUP-RECOVERY.md`。修改完成并通过测试后，应立即执行一次 `backup:step`。

## 主要目录

- `src/app/`：Next.js 页面与 API。
- `scripts/`：数据库、采集、通知和计划任务脚本。
- `scripts/sources.mjs`：已接入高校的来源、接口参数、频率限制和官方域名配置。
- `scripts/collector-registry.mjs`：采集器统一入口；每日任务按配置顺序采集北航、北理工、北交大和南开，单所失败不会阻止其他来源运行。
- `tests/`：采集、查询、审核和通知测试；`tests/fixtures/` 保存各高校公开接口或 HTML 页面的独立响应夹具。
- `data/`：本地数据库、快照和日志，均不应提交。
